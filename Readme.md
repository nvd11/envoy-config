# Envoy GCE Proxy

This project provides a complete setup for building a Google Compute Engine (GCE) image with Envoy proxy. The Envoy proxy is configured to act as a TCP proxy for a private Cloud SQL instance, but can be adapted for other use cases.

### File Descriptions

#### Root Directory

*   `cloudbuild.yaml`: Google Cloud Build configuration file. It defines the CI/CD pipeline for building the GCE image.
*   `cloudbuild_refresh_envoy_proxy.yaml`: Google Cloud Build configuration file. It defines the CI/CD pipeline for updating the managed instance group (MIG) with a new instance template.
*   `gce.pkr.hcl`: Packer configuration file for building the GCE image. It defines the base image, provisioners, and other parameters for the image build process.
*   `ENVOY_PROXY_GUIDE.md`: A detailed guide explaining the motivation behind using Envoy as a proxy for Cloud SQL and the troubleshooting steps taken.

#### `configs` directory

*   `configs/envoy.yaml`: The main template for the Envoy configuration. It contains the base configuration for Envoy, with placeholders for routes and clusters that are injected dynamically.
*   `configs/envoy_generated.yaml`: The final Envoy configuration file, generated by combining the `envoy.yaml` template with the route fragments from the `configs/routes/` directory.
*   `configs/routes/`: This directory contains the modular route configuration files. Each file defines a specific route and cluster for a service that Envoy will proxy.

#### `scripts` directory

*   `scripts/combine_routes.py`: A Python script that generates the final `envoy_generated.yaml` by combining the `configs/envoy.yaml` template with the route fragments in `configs/routes/`.
*   `scripts/setup_envoy.sh`: A shell script that is executed by Packer during the GCE image build process. It installs Envoy, downloads the configuration from GCS, and sets up the Envoy service.

#### `systemd` directory

*   `systemd/envoy.service`: A systemd unit file that defines how to run Envoy as a service on the GCE instance. It specifies the command to start Envoy, the user to run it as, and the restart policy.

## Deployment Flow

The deployment process is fully automated using Google Cloud Build and Packer.

1.  **Trigger Cloud Build**: A new build is triggered, typically by a push to the repository, which starts the `cloudbuild.yaml` pipeline.
2.  **Generate Envoy Configuration**: The `cloudbuild.yaml` pipeline first executes the `scripts/combine_routes.py` script. This script reads the `configs/envoy.yaml` template and all the route fragments in `configs/routes/` to generate the final `configs/envoy_generated.yaml`.
3.  **Upload to GCS**: The generated `envoy.yaml` (renamed from `envoy_generated.yaml`), `systemd/envoy.service`, and `scripts/setup_envoy.sh` are uploaded to a Google Cloud Storage (GCS) bucket.
4.  **Build GCE Image**: Cloud Build then uses Packer to build a new GCE image based on the `gce.pkr.hcl` configuration.
5.  **Provisioning**: During the image build process, Packer executes the `scripts/setup_envoy.sh` script. This script:
    *   Installs Envoy.
    *   Downloads the `envoy.yaml` and `envoy.service` files from the GCS bucket.
    *   Moves the downloaded files to the correct locations (`/etc/envoy/` and `/etc/systemd/system/`).
    *   Enables and starts the Envoy service.
6.  **Image Creation**: Once the provisioning is complete, Packer creates a new GCE image.
7.  **Rolling Update**: The `cloudbuild_refresh_envoy_proxy.yaml` pipeline is then triggered. It creates a new instance template from the newly created GCE image and performs a rolling update on the managed instance group (MIG).
8.  **Instance Creation**: The MIG replaces the old instances with new ones based on the new template, which will have Envoy running as a service with the latest configuration.

## Configuration Management

The Envoy configuration is managed in a modular way. The base configuration is in `configs/envoy.yaml`, and each service's routing configuration is in a separate file in `configs/routes/`. This makes it easy to add, remove, or modify the configuration for individual services without affecting the entire configuration.

The `scripts/combine_routes.py` script is responsible for combining these files into a single `envoy_generated.yaml` file that can be used by Envoy. This script is executed by the Cloud Build pipeline, ensuring that the configuration is always up-to-date.

## Usage

Once the GCE instance is running, you can connect to the services proxied by Envoy through the GCE instance's IP address and the port configured in `envoy.yaml`.
